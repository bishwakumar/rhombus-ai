# Test Datasets for Rhombus AI ETL Pipeline Evaluation

A fictional orders dataset for testing a Rhombus AI cleaning pipeline (GCS source → Rhombus AI → GCS destination). One messy baseline, its expected cleaned output, and seven drifted versions.

All files are generated by `generate_test_data.py` from a fixed seed (2026), so they can be regenerated identically:

```
python generate_test_data.py
```

## Naming convention

Every test case has one ID, used everywhere in the repo:

`<number>-<category>-<change>`

- **number** keeps files in test order (00 to 07)
- **category** is `baseline`, `schema` or `semantic`
- **change** says what was changed

The same ID is reused for the saved output (`outputs/01-schema-drop-column__run1.csv`), the observation file (`observations/01-schema-drop-column.md`) and its evidence folder (`observations/evidence/01-schema-drop-column/`).

The 500 source rows are 470 unique orders, 20 exact duplicate rows and 10 rows that repeat an `order_id` with a different amount and status. Each duplicate sits directly below its original row.

## Columns and planted problems

| Column | Meaning | Problems planted in the baseline |
|---|---|---|
| `order_id` | Order number (10001–10470) | Exact duplicate rows; repeated IDs with a different amount and status |
| `customer_name` | Customer name | ALL CAPS, all lower case, mixed case (`RUBY novak`), extra spaces, missing |
| `email` | Customer email | UPPER CASE, placeholders (`n/a`, `none`, `-`), invalid (`name@`, `_at_`), missing |
| `order_date` | Order date | MM/DD/YYYY, MM-DD-YYYY, ISO, text (`March 8 2026`), invalid (`TBD`, `13/45/2026`), missing |
| `amount_usd` | Order value in dollars | `$1,361.98`, `$ 1297.92`, `1617.84 USD`, fewer decimals (`403.5`), negative, non-numeric (`abc`, `free`), missing |
| `quantity` | Units ordered | Words (`five`), `2.0`, `1.5`, zero or negative, missing |
| `country` | Customer country | `AU`, `AUS`, `USA`, `U.S.`, `GB`, `NZ`, `INDIA`, missing |
| `status` | Order status | `PENDING`, `Shipped`, trailing spaces, invalid (`xyz`, `unknown`), missing |

## Cleaning rules (followed by `00-baseline.expected.csv`)

1. Remove exact duplicate rows, then keep the first row for each `order_id`.
2. `customer_name`: trim, title case.
3. `email`: trim, lower case; blank if invalid or a placeholder.
4. `order_date`: YYYY-MM-DD; slash and dash dates are month first; blank if invalid.
5. `amount_usd`: strip `$`, commas, spaces and `USD`; exactly 2 decimals; blank if negative or non-numeric.
6. `quantity`: whole number (words converted, `2.0` becomes `2`); blank if zero, negative or a fraction.
7. `country`: full canonical name (Australia, United States, United Kingdom, New Zealand, India).
8. `status`: trim, lower case; blank unless shipped, delivered, pending or cancelled.

## Detecting the semantic drift

- **06-semantic-cents:** valid amounts in the baseline are $11.87 to $1,998.49. Here they range from 1,187 to 199,849.
- **07-semantic-date-swap:** true dates are only January to March 2026, on day 1–12. After the swap, parsed dates spread across all 12 months, and some fall in the future.

## How to run a test case

The pipeline always reads one fixed, neutral file name, so the input name never misleads. Copy the case's file over it, run the pipeline, then save the output under the case ID:

```
# load the case
gcloud storage cp datasets/01-schema-drop-column.csv gs://rhombus-source/input/orders.csv

# after the run, keep a readable copy of Rhombus's timestamped output
gcloud storage cp gs://rhombus-output/RhombusAI_output_<timestamp>.csv outputs/01-schema-drop-column__run1.csv
```

Restore `00-baseline.csv` between test cases, and record each run in `results/runs.csv`.
